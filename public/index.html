Pilot Desk for Keenable search

Their queries, not ours.

Pick a prospect, or paste the queries their agent really sends. Pilot Desk runs each one live through Keenable's Search API in both modes, checks whether the source an evaluator expects comes back near the top, and writes an honest first read you could hand the Head of Revenue.

Independent prototype. It calls Keenable's documented keyless endpoint (/v1/search/public) from a server in US East. Not made or endorsed by Keenable.

Where the next keyless default comes from.

      
Keenable already ships inside Lightpanda, LibreChat, ZeroClaw and Baseten. This is the next list: agent frameworks, runtimes and inference platforms that don't list Keenable yet, what search they ship today (from their own docs), and the first move for each.

      
Prepared in advance with Keenable search and fetch. Every provider claim links to the page it came from. First-touch notes are drafts for this demo; nothing was sent.

    

    

      

        
Play 1 · platform, paid per call

        
OpenRouter: "keenable" as a web-plugin engine

        
Integration (proposed): an adapter that maps Keenable results onto the plugin's existing engine interface and citation format, next to native, Exa, Firecrawl, Parallel and Perplexity.

        
Acceptance test: their own sample of web-plugin queries, run through the current default and Keenable; compare answer quality, p95 latency and cost per request.

        
Next decision: whether they'd list a new engine value, and on what volume terms.

        
Path to revenue: platform-metered usage, the same shape as Baseten, where calls land on the platform's invoice.

      

      

        
Play 2 · framework, keyless default

        
Letta: web search that works self-hosted

        
Integration (proposed): use Keenable's keyless endpoint for web_search when no EXA_API_KEY is set, like Lightpanda's no-key fallback.

        
Acceptance test: a fresh Docker install answers a web question with no keys configured; maintainers' CI passes.

        
Next decision: whether maintainers take the PR and a provider flag.

        
Path to revenue: keyless traffic identified by its app title shows who's growing; heavy users move to keys, credits, then accounts.

1
Own the technical win
Turn Pilot Desk into the standard first meeting: the prospect's own queries, live, in 15 minutes, before anyone asks for a benchmark. Every run leaves a shareable first read and a sized deal.

      
2
Build the demo and the integration
Ship the harness adapters labs actually run (Inspect-style eval tasks, a LangGraph/Agents-SDK tool, a Baseten hosted-tool example) so "stand Keenable up in your stack" takes an afternoon, not a sprint.

      
3
Run evaluations to a verdict
Default every pilot to point-in-time search (query_time): retrieval is pinned to one index state, so the lab can rerun the eval next week against the same pages. Success criteria and a date are agreed on day one.

      
4
Own the platform channel
Work the Channel radar: one upstream PR a week that makes Keenable the no-key fallback, like Lightpanda. Each merged default is a self-serve funnel that feeds accounts.

      
5
Bring back what they need
Log every query where the expected source missed the top 3 and bring that list to Matthias and the team every week. Run a pilot on the first tab and your misses show up here.
