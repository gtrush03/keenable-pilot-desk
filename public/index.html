Pilot Desk for Keenable search

Their queries, not ours.

Pick a prospect, or paste the queries their agent really sends. Pilot Desk runs each one live through Keenable's Search API in both modes, checks whether the source an evaluator expects comes back near the top, and writes the verdict you'd hand the Head of Revenue.

Independent prototype. It calls Keenable's documented keyless endpoint (/v1/search/public) from a server in US East. Not made or endorsed by Keenable.

Week one, as the founding GTM hire.

      
The job post in five lines, and what I'd do with each in the first week.

    

    

      
1
Own the technical win
Turn Pilot Desk into the standard first meeting: the prospect's own queries, live, in 15 minutes, before anyone asks for a benchmark. Every run leaves a shareable verdict and a sized deal.

      
2
Build the demo and the integration
Ship the harness adapters labs actually run (Inspect-style eval tasks, a LangGraph/Agents-SDK tool, a Baseten hosted-tool example) so "stand Keenable up in your stack" takes an afternoon, not a sprint.

      
3
Run evaluations to a verdict
Default every pilot to point-in-time search (query_time): the index is frozen, so the lab can rerun the same eval next week and get the same answer. Success criteria and a date are agreed on day one.

      
4
Own the platform channel
Work the Channel radar: one upstream PR a week that makes Keenable the no-key fallback, like Lightpanda. Each merged default is a self-serve funnel that feeds accounts.

      
5
Bring back what they need
Log every query where the expected source missed the top 3 and bring that list to Matthias and the team every week. Run a pilot on the first tab and your misses show up here.
